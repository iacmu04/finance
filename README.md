# คู่มือการติดตั้งและใช้งานระบบติดตามงานตรวจสอบงบการเงิน (Finance Report Tracking System)
สำนักงานตรวจสอบภายใน มหาวิทยาลัยเชียงใหม่

## 1. ภาพรวมโครงสร้างไฟล์ในระบบ

ระบบถูกแยกไฟล์อย่างเป็นสัดส่วนตามข้อกำหนด ดังนี้:

| ชื่อไฟล์ | หน้าที่และรายละเอียด |
| :--- | :--- |
| **`Code.gs`** | Backend API (Google Apps Script) ทำหน้าที่เชื่อมต่อ Google Sheets โดยตรง, จัดการระบบสิทธิ์ (RBAC), ตรวจสอบความถูกต้อง, ล็อกข้อมูลพร้อมกันด้วย LockService และบันทึกประวัติ SystemLog |
| **`Index.html`** | โครงสร้างหน้าเว็บหลัก (HTML Layout) สำหรับรันบน Google Apps Script Web App มีระบบแท็บ (Dashboard, ติดตามงาน, ทะเบียนส่วนงาน, ตั้งค่าระบบ) และ Modals บันทึกงาน |
| **`Stylesheet.html`** | รวม CSS สำหรับแสดงผลใน Apps Script (สไตล์ทางการ สะอาดตา ทันสมัย สไตล์ มช. สีม่วง-น้ำเงิน-เทา) |
| **`JavaScript.html`** | รวมสคริปต์ Frontend สำหรับรันบน Apps Script ดึง Session Email จาก Google อัตโนมัติ |
| **`style.css`** | ไฟล์ CSS ต้นฉบับสำหรับแก้ไขหรือใช้ใน standalone |
| **`api.js`** | ตัวเชื่อมต่อ API (รองรับทั้ง `google.script.run` และ Fetch REST API) |
| **`app.js`** | ตรรกะการประมวลผล Frontend, การกรองสิทธิ์, การคำนวณ KPI และงบค้างส่งที่ไม่เป็นปัจจุบัน |
| **`standalone_preview.html`** | หน้าเว็บแบบแยกไฟล์สำหรับเปิดดูพรีวิวและทดสอบบนเครื่องคอมพิวเตอร์ได้ทันที |

## 2. ขั้นตอนการติดตั้งบน Google Apps Script (Step-by-Step)

### ขั้นตอนที่ 1: เปิด Google Apps Script จาก Google Sheets
1. เปิดไฟล์ Google Spreadsheet: [Finance Report](https://docs.google.com/spreadsheets/d/1BFzdwv5j7nRqvnzjFUHZpxScs2hZz80ZrBRYkipLBdM/edit)
2. ไปที่เมนูด้านบน เลือก **ส่วนขยาย (Extensions)** > **Apps Script**

### ขั้นตอนที่ 2: วางโค้ดลงในโปรเจกต์ Apps Script
1. ในหน้าต่าง Apps Script ให้สร้าง/แทนที่ไฟล์ดังนี้:
   * **ไฟล์ `Code.gs`**: คัดลอกเนื้อหาจากไฟล์ `Code.gs` ในโฟลเดอร์นี้ไปวางแทนที่ทั้งหมด
   * **ไฟล์ HTML ชื่อ `Index.html`**: กดปุ่ม `+` ข้างหัวข้อ "ไฟล์" > เลือก **HTML** > ตั้งชื่อว่า `Index` > คัดลอกเนื้อหาจาก `Index.html` ไปวาง
   * **ไฟล์ HTML ชื่อ `Stylesheet.html`**: กดปุ่ม `+` > เลือก **HTML** > ตั้งชื่อว่า `Stylesheet` > คัดลอกเนื้อหาจาก `Stylesheet.html` ไปวาง
   * **ไฟล์ HTML ชื่อ `JavaScript.html`**: กดปุ่ม `+` > เลือก **HTML** > ตั้งชื่อว่า `JavaScript` > คัดลอกเนื้อหาจาก `JavaScript.html` ไปวาง
2. กดปุ่ม **บันทึกโครงการ (Save Project)** 💾

### ขั้นตอนที่ 3: เผยแพร่เป็นเว็บแอปพลิเคชัน (Deploy as Web App)
1. กดปุ่มสีน้ำเงิน **ทำให้ใช้งานได้ (Deploy)** ที่มุมขวาบน > เลือก **การทำให้ใช้งานได้รายการใหม่ (New deployment)**
2. คลิกที่ไอคอนเฟือง ⚙️ ด้านซ้าย > เลือก **เว็บแอป (Web app)**
3. ตั้งค่าการเผยแพร่ดังนี้:
   * **คำอธิบาย (Description):** `Finance Report Tracking System v1.0`
   * **เรียกใช้ในฐานะ (Execute as):** `ผู้ใช้ที่เข้าถึงเว็บแอป (User accessing the web app)` เพื่อให้อ่านบัญชี Gmail/CMU Mail ของผู้เข้าใช้งานจริง
   * **ผู้มีสิทธิ์เข้าถึง (Who has access):** `ทุกคนในโดเมนมหาวิทยาลัยเชียงใหม่` หรือ `ทุกคน (Anyone)` ตามนโยบายของสำนักงาน
4. กดปุ่ม **ทำให้ใช้งานได้ (Deploy)** และให้สิทธิ์การเข้าถึงข้อมูล (Authorize access)
5. คัดลอก **URL เว็บแอป (Web App URL)** สำหรับนำไปแจกจ่ายให้ผู้บริหารและผู้ตรวจสอบใช้งาน

## 3. ตรรกะการทำงานและฟีเจอร์สำคัญของระบบ

### 3.1 การยืนยันตัวตนและการจำกัดสิทธิ์ (Google Login & RBAC)
* ระบบจะตรวจจับอีเมล Google ของผู้ใช้ผ่าน `Session.getActiveUser().getEmail()` แล้วนำไปค้นหาในชีท **`ผู้ตรวจสอบ`**
* **Admin (`E370012` ปุ้ย):** สิทธิ์เต็ม เข้าถึงทุกหน้า จัดการทะเบียนส่วนงาน และแก้ไขเกณฑ์ KPI 20 วันได้
* **Dean (ผอ. `D370002` หยก):** เห็นภาพรวมทุกกลุ่มงาน, เห็นสถิติการส่งกลับแก้ไขและเวลารวมที่ใช้แก้ไข, มีปุ่ม "ผอ. เห็นชอบรายงาน" และ "เสร็จสิ้นและเสนออธิการบดี"
* **Leader (หัวหน้ากลุ่มงาน):** เห็นเฉพาะงานทั้งหมดในสังกัดกลุ่มงานของตนเอง และงานของสมาชิกในกลุ่ม
* **User (ผู้ตรวจสอบ):** เห็นเฉพาะงานที่ตนเองรับผิดชอบและงานในกลุ่มงานตนเอง
* *หมายเหตุ:* ในแถบด้านบนจะมีเมนู **"มุมมองสิทธิ์"** ให้เลือกสลับดูมุมมองจำลองของแต่ละ Role ได้ เพื่อความสะดวกในการตรวจสอบหน้าจอ

### 3.2 การติดตาม "งบการเงินที่ไม่เป็นปัจจุบัน (Lagging Periods)"
* ตัวชี้วัดพิเศษบน Dashboard จะเปรียบเทียบงวดรายงานของแต่ละส่วนงานกับเดือนปัจจุบัน
* หากส่วนงานใดยังไม่มีการส่งงบตามกำหนด (ปกติส่งไม่เกินวันที่ 20 ของเดือนถัดไป) เช่น ปัจจุบันเดือน พฤศจิกายน แต่งบล่าสุดคือ เมษายน ระบบจะคำนวณและแสดงเตือนรายการงบค้างส่งที่ไม่เป็นปัจจุบันทันที พร้อมจำนวนงวดที่ค้าง

### 3.3 การคำนวณ KPI ระยะเวลา 20 วันปฏิทิน
* **เริ่มนับ:** จากวันที่ผู้ตรวจสอบได้รับงบ (คอลัมน์ H)
* **สิ้นสุด:** วันที่เสนองบให้ ผอ. (คอลัมน์ J)
* **เกณฑ์:** $\le 20$ วัน = **ทันกำหนด (เขียว)**, $> 20$ วัน = **เกินกำหนด (แดง)** (นับรวมวันหยุดเสาร์-อาทิตย์และวันหยุดนักขัตฤกษ์)
* Admin สามารถปรับเปลี่ยนเกณฑ์จำนวนวันได้ในหน้า **การตั้งค่าระบบ** ซึ่งจะถูกบันทึกลงชีท `Config`

### 3.4 การส่งกลับแก้ไข (Edit History - Transaction-based)
* บันทึกแยกเป็นรอบอิสระในชีท `Edit` รองรับไม่จำกัดรอบ
* คำนวณจำนวนวันแก้ไขอัตโนมัติ: วันที่ส่งคืน ผอ. − วันที่ ผอ. ส่งกลับ
* แสดงสถิติการส่งกลับแก้ไขและเวลารวมที่ใช้แก้ไขเฉพาะผู้บริหาร (Dean) และ Admin เท่านั้น

### 3.5 การเปลี่ยนตัวผู้รับผิดชอบส่วนงาน
* เมื่อมีการมอบหมายผู้รับผิดชอบใหม่ในหน้าทะเบียนส่วนงาน ระบบจะอัปเดตสถานะของแถวเดิมเป็น **"ยกเลิก"** และสร้างแถวใหม่ที่มีสถานะเป็น **"ใช้งาน"** ทันที เพื่อเก็บประวัติไว้ตามข้อกำหนด

### 3.6 การบันทึก SystemLog
* การดำเนินการสำคัญทุกรายการ เช่น การสร้างงวดงาน, การบันทึกวันที่, การเห็นชอบของ ผอ., การเสนออธิการบดี, และการกดยกเลิกพร้อมเหตุผล จะถูกบันทึกประวัติลงในชีท `SystemLog` เสมอ
